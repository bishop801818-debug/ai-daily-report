【早报 JSON 输出格式规范 — 请严格按此格式生成】

从今日起，所有事业部的早报直接生成 JSON 文件（不再生成 docx），JSON 格式必须严格按照模板，否则下游系统无法识别。

========================================================================
一、顶层结构（每个 BU 一个文件）
========================================================================

文件名：YYYY-MM-DD-<bu_id>.json
例如：2026-06-26-czly.json

{
  "bu_id": "czly",
  "name": "常州锂源事业部",
  "date": "2026-06-26",
  "header": {
    "日期": "2026-06-26",
    "事业部": "常州锂源事业部",
    "核心结论": "（填写本事业部今日核心结论）"
  },
  "sections": [ ... ]
}

⚠️ 注意：sections 必须是「数组 []」，不能是「字典 {}」！


========================================================================
二、每个 item 必须有这 6 个英文字段（所有 section 通用）
========================================================================

| 字段名    | 类型   | 说明                        |
|-----------|--------|-----------------------------|
| title     | 字符串 | 条目标题（必填）            |
| content   | 字符串 | 正文/摘要（必填，不能为空！）|
| priority  | 字符串 | P0 / P1 / P2（必填）       |
| source    | 字符串 | 来源 + 日期（必填）          |
| url       | 字符串 | 原文链接（可为空字符串 ""） |
| date      | 字符串 | YYYY-MM-DD（必填）          |

❌ 禁止使用：标题、摘要、来源、日期、序号（中文键名）
✅ 必须使用：title、content、priority、source、url、date（英文键名）


========================================================================
三、各 section 具体格式要求
========================================================================

--- 1. 今日关注（dim: "topnews"）---

  "items": [
    {
      "title": "标题文字",
      "content": "正文内容（展开后显示的文字）",
      "priority": "P1",
      "source": "来源名称，2026-06-26",
      "url": "",
      "date": "2026-06-26"
    }
  ]
  → 3-5 条


--- 2. 市场/价格（dim: "market"）---

  ❌ 禁止分成"价格数据表""供给信号""争议风险"三块
  ✅ 必须将三块内容全部「展平」为一条条独立 item

  价格数据表的每一行 → 一条 item（title=品类名，content=价格+涨跌+来源）
  供给信号每条 → 一条 item（title=信号标题，content=正文）
  争议风险每条 → 一条 item（title=风险标题，content=正文）

  → 共约 12-15 条，不是 1 条嵌套字典！

  {
    "title": "碳酸锂期货LC2609主力",
    "content": "价格：162740元/吨\n涨跌：+6160元/吨（+3.93%）\n来源：广期所，2026-06-25",
    "priority": "P1",
    "source": "广期所，2026-06-25",
    "url": "",
    "date": "2026-06-25"
  }


--- 3. 政策/行业（dim: "policy"）---

  → 3-5 条，每条 content 必须有完整摘要正文


--- 4. 企业动态（dim: "enterprise"）---

  → 3-5 条，每条 content 必须有完整摘要正文


--- 5. 技术/产品（dim: "tech"）---

  → 2-4 条，每条 content 必须有完整摘要正文


--- 6. 项目/招标（dim: "project"）---

  → 2-4 条，每条 content 必须有完整摘要正文


--- 7. 专属提示（dim: "tips"）---

  ✅ 必须有且只有 4 条，每条对应一个分类：

  {
    "title": "💰 机会",
    "content": "（机会内容文字）"
  },
  {
    "title": "⚠️ 风险",
    "content": "（风险内容文字）"
  },
  {
    "title": "📋 行动建议",
    "content": "（行动建议内容文字）"
  },
  {
    "title": "👁️ 重点关注",
    "content": "（重点关注内容文字）"
  }

  ❌ 禁止写成 {"机会": [{"总结": "..."}]} 这种嵌套格式！


========================================================================
四、自检清单（生成后必须检查，全部打勾才能通过）
========================================================================

[ ] sections 是数组（[ 开头），不是字典（{ 开头）
[ ] 每个 item 的键名全是英文（title/content/source/date）
[ ] content 字段都有值（不为空字符串）
[ ] tips 的 items 有 4 条，title 含 emoji（💰/⚠️/📋/👁️）
[ ] market 的 items 有 12 条以上（不是 1 条嵌套字典）
[ ] 文件命名格式正确：YYYY-MM-DD-<bu_id>.json


========================================================================
五、操作步骤
========================================================================

1. 按模板格式生成各事业部 JSON 文件
2. 按「四、自检清单」逐项检查
3. 将 JSON 文件保存到指定目录（不再生成飞书 docx）
4. 先用 2026-06-26 的数据试运行一次
5. 将生成的 JSON 文件发给用户确认格式无误
6. 确认无误后正式切换为 JSON 输出模式

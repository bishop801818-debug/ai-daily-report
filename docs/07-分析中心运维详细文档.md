**重要规则**：

### 2.2 月份选择器机制

`analysis_hub.html` 卡片的"查看报告"按钮旁有月份下拉选择器：

```
[📊 查看报告（2026年05月）] [▾]
                             ├── 2026年05月
                             └── 2026年04月
```

- 月份列表由 `REPORT_LIST` 中的 `availableMonths` 数组驱动
- 新报告生成时，`generate_monthly_report.py` 自动追加新月到数组
- 碳酸锂等只有一个报告的行业，显示为简单按钮（无下拉）

## 三、报告生成流水线

### 3.1 整体架构

```
Layer 3: AI 叙事撰写（Phase B，需人工触发 Skill）
  ↑
Layer 2: 结构化事件简报 events_brief.json（extract_events.py）
  ↑
Layer 1: 原始数据源
  ├── industry_news_clean.json（2,476 条行业新闻）
  ├── policy_center_embedded_data.js（政策数据）
  ├── reports/*.json（每日早报）
  └── cninfo_announcements.json（交易所公告）
```

### 3.2 关键脚本

| 脚本 | 位置 | 功能 |
|------|------|------|
| `extract_events.py` | `D:\buddy\skills\lithium-analysis-report\` | 从4个数据源提取、去重、分类事件 |
| `generate_report.py` | 同上 | 计算 KPI、构建表格、预填数据占位符 |
| `generate_monthly_report.py` | 同上 | 月度自动化入口：调用上述脚本 + 保存 + 更新 hub |
| `narrative_framework.md` | 同上 | AI 叙事写作框架和标准 |
| `inject_narratives.py` | 同上 | 将 AI 撰写的叙事注入报告 HTML |

### 3.3 完整生成流程

#### Phase A：数据提取 + 报告骨架（可自动化）

```bash
cd D:\buddy\skills\lithium-analysis-report
py -3.12 generate_monthly_report.py lfp --month 2026-04
```

执行步骤：
1. **提取事件**：`extract_events.py lfp --month 2026-04` → `events_brief.json`
   - 从行业新闻库筛选 czly/lpsd/sjld 部门事件（日期范围：报告月前90天至报告月末）
   - 从政策中心匹配 BU 标签
   - 从近30天早报提取对应维度条目
   - 去重（Jaccard 相似度 > 0.75 或 同日期+同企业）
   - 分类（产能布局/订单合作/技术产品/政策法规/海外扩张/价格波动/资本运作）
2. **生成骨架**：`generate_report.py` 计算 KPI、构建表格、预填图表数据
3. **保存文件**：复制为 `lfp_report_{YYYY}_{MM}.html`
4. **更新 Hub**：在 `analysis_hub.html` 的 `availableMonths` 数组中追加新月

#### Phase B：AI 叙事撰写（需人工触发 Skill）

1. 调用 Skill：`/lithium-analysis-report`
2. AI 读取 `events_brief.json` + `narrative_framework.md`
3. 逐节撰写深度分析文字：
   - 1.1 行业动态 → 事件表 + 主题聚类叙事
   - 1.2 产量分析 → 供需拆解（动力+储能双轮驱动）
   - 1.3 竞对视角 → 头部企业逐个分析
   - 1.4 客户视角 → 下游采购格局
   - 1.5 出口分析 → 量价趋势 + 贸易风险
   - 1.6 价格分析 → 成本传导 + 产品结构
   - Part 2-4 → 上游原料/磷酸铁/碳酸锂
   - Part 5 → 总结与建议
4. **防呆规则**：AI **只能引用 `events_brief.json` 中的事件**，不得使用报告月之后的信息。例如写4月报告时，5月发生的事件不可引用（`extract_events.py` 通过 `end_date` 截止到次月首日来自动过滤）

## 五、页面 JS 数据结构

### 5.1 REPORT_LIST 条目说明

```javascript
{
    id: 'lfp',                    // 行业标识，对应文件名前缀
    name: '磷酸铁锂数据库',         // 卡片显示名称
    icon: '🔋',                   // 卡片图标
    desc: '...',                  // 描述文字
    done: true,                   // 是否已完成报告
    reportBase: 'lfp_report',     // 报告文件名前缀（多月报告用）
    availableMonths: ['2026-05', '2026-04'],  // 可用月份列表（降序）
    dataHref: 'lfp_data_v2.html', // 数据库子页链接
    chartHref: 'lfp_charts.html', // 可视化看板链接
    tabs: '6个Tab',              // 报告结构说明
    charts: '14个图表',           // 图表数量
}
```

- 有 `reportBase` + `availableMonths` → 显示月份下拉选择器
- 仅有 `reportHref` → 显示简单按钮（单报告行业，如碳酸锂）

### 5.2 添加新月份

当新报告生成后，`generate_monthly_report.py` 会自动更新 `availableMonths` 数组。如需手动添加：

1. 编辑 `analysis_hub.html`
2. 找到对应行业的 `availableMonths: ['...']`
3. 在数组**开头**插入新月份（保持降序）
4. 确保对应的 `{reportBase}_{YYYY}_{MM}.html` 文件存在

## 六、常见问题与排障

### 6.1 报告显示"5月信息分析4月数据"（张冠李戴）

**根因**：AI 在撰写叙事时使用了报告月之后的知识。

**预防**：`extract_events.py` 的 `end_date` 截止到次月首日，自动过滤后续事件。AI 撰写时必须严格遵守 `narrative_framework.md` 中的防呆规则。

**修复**：手动编辑报告 HTML，替换/删除跨月信息。参见 2026-05-31 存档的修复案例。

### 6.2 月份下拉不显示新月

**排查**：
1. 确认 `analysis_hub.html` 的 `availableMonths` 是否包含新月
2. 确认对应的 `lfp_report_{YYYY}_{MM}.html` 文件是否存在
3. 清除浏览器缓存后刷新

### 6.3 extract_events.py 事件数量过少

**排查**：
1. 检查 `end_date` 是否设置正确（应为报告月次月首日）
2. 检查行业新闻库 `industry_news_clean.json` 更新时间
3. 检查早报文件 `reports/*.json` 是否覆盖了完整日期范围
4. 调整 `--days` 参数扩大回溯范围（默认 90 天）

### 6.4 events_brief.json 中缺少关键事件

**排查**：
1. 检查事件所属 dept 是否在 `INDUSTRY_MAP` 的 `news_dept` 或 `related_depts` 中
2. 检查 `MIN_TITLE_LEN` 是否过滤了短标题的有效事件
3. 检查去重阈值是否过高（默认 Jaccard > 0.75）
